# MoreRecords 0.1.0b2 — Beta 2

**Experimental pre-release for Home Assistant.** This update builds on `0.1.0b1` and includes the latest `main` work on historical Recorder merging and a configurable transition state for the gap between imported and existing history.

## Changes since 0.1.0b1

- **Exact-timestamp merging:** source observations from CSV or CCU-Historian are inserted at timestamps missing from the target entity's Recorder history, including timestamps inside the currently recorded period. The previous version excluded that entire period.
- **Existing Home Assistant states take precedence:** when a source row shares a timestamp with a stored Recorder row, the existing row is kept, even if the values differ. Such disagreements appear in the import preview.
- **Three required bridge policies** for the interval after the last imported source observation *before* the first original Recorder state:
  - **Hold last state of import** (`hold_last`): carry the imported state forward until the first existing HA entry.
  - **Use oldest state of Recorder** (`oldest_recorder`): insert a synthetic state change one microsecond after the last imported prefix value, using the first original Recorder state.
  - **Unavailable** (`unavailable`): insert a synthetic `unavailable` state one microsecond after the last imported prefix value, ending at the original first HA entry.
- **Import preview:** shows missing observations, equal-timestamp conflicts, excluded points beyond the latest HA state, retention skips, selected bridge mode, and any planned synthetic marker.
- **Safer Recorder writes:** recomputes the merge plan in the Recorder writer transaction and refuses writes if stored-history content or import eligibility has changed since preview. Existing Recorder values, timestamps, and attributes are not replaced. Only new rows and their directly affected chronological predecessor links are updated.
- **LightAway-oriented continuity checks:** complete-source confirmation for CCU-Historian is optional. An import does not itself imply a verified continuous history; a certificate requires an exact source-to-Recorder match. Synthetic bridge states do not qualify as measured CCU-Historian evidence.
- Updated **English and German** user interface text, development documentation, and automated regression tests.

## Features retained from 0.1.0b1

- Import existing Recorder entity history from timestamp/value CSV or directly from searchable CCU-Historian datapoints via JSON-RPC.
- Import `light`, `switch`, `binary_sensor`, `sensor`, and other existing recorded Home Assistant entities with domain-aware validation.
- Respect `recorder.auto_purge` and `purge_keep_days`.
- Resolve CCU-Historian same-timestamp conflicting observations by keeping the last source observation.
- Export retained raw Recorder states as CSV over a selected time window.
- HACS-compatible package with German and English configuration flows.

## Installation / update

Add `https://github.com/derhopp/MoreRecords` to HACS as a custom **Integration** repository if needed. Enable the display of prerelease/beta versions if necessary, select **`0.1.0b2`**, and restart Home Assistant. The manifest version and Git tag both use `0.1.0b2`.

Home Assistant minimum version declared by `hacs.json`: **2026.10.0**. Historical import currently supports **SQLite Recorder databases only**.

## Important beta limitations

- **Create and verify a restorable Home Assistant backup before importing.** MoreRecords writes to private Recorder tables; schema and transaction behavior may change between Home Assistant versions.
- Imported data never changes the currently running entity state and does not replay historic `state_changed` events or device-service calls.
- Source readings newer than the latest existing Recorder state are **not** imported, to avoid altering the live end of the history.
- The selected bridge policy applies only to the **leading gap** between a newly imported prefix and the first original Recorder state. It does not interpolate or synthesize missing values inside the stored interval.
- A bridge marker is an operator-selected assumption, **not** an actual CCU-Historian measurement. Do not treat it as verified LightAway history.
- Automatic Recorder purging can remove imported points as the retention window advances.
- Live Home Assistant/SQLite integration testing of the Recorder state-chain changes is still required. Passing Python tests, Hassfest and HACS validation does not guarantee runtime compatibility.

**This is a prerelease, not a stable release.** Issues and development verification work are tracked at https://github.com/derhopp/MoreRecords/issues/1.
