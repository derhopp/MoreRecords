# MoreRecords 0.1.0b1 — first beta prerelease

This is the first **experimental prerelease** of the MoreRecords custom integration for Home Assistant.

## Included features

- **Historical CSV import** into existing Home Assistant Recorder entities, including lights, switches, binary sensors, and numeric or textual sensors, without changing live entity state.
- **Direct CCU-Historian import** using a configurable JSON-RPC endpoint, searchable datapoints (name/parameter/interface/address), and selectable date ranges.
- **Retention- and overlap-aware import:** honors the configured `auto_purge`/`purge_keep_days` and avoids replacing existing Recorder history.
- **Source collision handling:** CCU-Historian observations sharing a timestamp retain the last state returned for that timestamp, with logged and previewed conflict counts.
- **Recorder CSV export** of original state rows for a selectable time interval, delivered through short-lived authenticated download links.
- **German and English UI translations**, HACS integration layout, English documentation, and automated tests.

## LightAway-related historical coverage changes

The latest `main` changes are included in this beta:

- **Optional CCU-Historian continuity/coverage attestations** requiring explicit user confirmation of a complete source query.
- **Exact Recorder verification** of the requested source history before recording an attestation.
- **Entity-scoped content fingerprints** to ensure recorded evidence becomes invalid if the stored history changes or is purged.
- **Safe handling of reverified overlapping provenance:** valid new coverage can supersede earlier evidence only under the repository's verification policy.

A coverage attestation represents **verified source and stored history**, not the retroactive firing of `state_changed` events. MoreRecords does **not** replay historical device actions or button presses.

## Installation

Add `https://github.com/derhopp/MoreRecords` as a **custom integration repository** in HACS. Enable prerelease/beta selection if needed, then choose tag `0.1.0b1` and restart Home Assistant. Alternatively, copy `custom_components/more_records` from this tag into `config/custom_components/`.

Minimum Home Assistant version indicated in `hacs.json`: **2026.10.0**. The Recorder implementation has private API dependencies and is especially sensitive to Home Assistant Core version changes.

## Beta warnings and limitations

- **Make and verify a full backup before importing.** This beta writes directly to internal Recorder SQLite tables and is not guaranteed compatible with all Home Assistant releases.
- The data-import path remains **SQLite-only**. Importing past history does not generate long-term statistics, change current entity states, or replay past events.
- Records older than the active Recorder retention window are skipped when `auto_purge` is enabled; existing stored intervals are protected.
- CSV and CCU-Historian imports are bounded in size; reduce the selected date interval if necessary.
- The complete import/download experience still needs validation against real Home Assistant installations; automated tests and HACS/Hassfest checks are not a substitute.
- This beta is **not** a stable general-availability release.

Please report any issues at https://github.com/derhopp/MoreRecords/issues. Development acceptance criteria and known limitations remain tracked in issue #1.
