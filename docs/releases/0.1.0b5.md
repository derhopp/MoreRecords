# MoreRecords 0.1.0b5 — Beta 5

**Experimental pre-release** built from the **exact 0.1.0b3 source tree**, with only the new opt-in import feature. The withdrawn `0.1.0b4` prerelease and its separate rolling-retention-anchor implementation are NOT included.

## Opt-in daily midnight support rows for sparse histories

- A new checkbox **Create daily 00:00 support rows from imported observations** is **off by default** in the import wizard. It works for CSV and CCU-Historian imports.
- Within the user's chosen import window, compute each midnight in **Home Assistant's local time zone**, including DST changes. Carry forward the most recent **genuinely observed source state** at or before midnight. Never use current state, unrelated Recorder states or earlier generated support rows as evidence for the value.
- Do **not** generate a midnight support row if **any** actual source or existing Home Assistant Recorder observation is present during the local **[00:00, 06:00)** window.
- Support **timestamps must satisfy the active Recorder retention cutoff**. A real source observation older than the cutoff may still seed the **first eligible midnight** within the user's selected import window, but that older observation is not reinserted in Recorder.
- Retain exact-time collision protection, Recorder-authoritative values and the wizard's explicitly selected leading-gap policy. Preview shows how many synthetic daily support points are planned; the Recorder writer rechecks the complete plan and state snapshot before inserting anything.
- Daily points copy the most recent observed **value**, not an invented/interpolated value. The midnight **timestamp is synthetic** and does not represent a measured event. The generated points cannot certify CCU-Historian source completeness.
- When enabled for CCU-Historian, the importer fetches the *entire user-selected time window* rather than truncating the request at the purge boundary, to identify an eligible pre-cutoff anchor. Data retrieval may be larger than usual.

## Important boundaries

- CSV imports use the timestamp span covered by source observations as their window; CCU-Historian uses the user's selected start and end dates.
- No midnight marker is inserted before the first actual source observation or after the newest existing Recorder state. Already recorded source or Recorder samples between midnight and 06:00 suppress a support marker for the corresponding day.
- The optional feature does not change original states, nor does it infer unrecorded intermediate transitions; it does **not** establish evidence of a complete series.
- All normal `auto_purge`, SQLite-only and verified-coverage limitations from `0.1.0b3` remain in effect. A full Home Assistant backup and testing on your precise HA version are strongly recommended.

## Installation

In HACS, enable pre-releases for `https://github.com/derhopp/MoreRecords`, select **0.1.0b5**, install and restart Home Assistant. Under **MoreRecords → Configure → Import**, explicitly enable daily support rows when needed. Existing releases remain available, except withdrawn beta 4.
